왜 이 칸부터인가

최소판(질문을 그대로 검색어로 써서 한 번 검색하고, 가져온 청크 8개로 답하는 지금 시스템)은 질문 38개 가운데 31개에서 근거가 든 청크를 가져왔습니다. 놓친 질문 7개는 모두 근거가 한국어 문서에만 있습니다. 그 가운데 5개는 영어 질문이고, 2개는 한국어 표 질문입니다.

답으로 보면 최소판이 틀린 답 46개 가운데 35개가 이렇게 검색이 근거를 놓친 경우였습니다. 질문 38개를 씨앗(같은 질문을 다시 돌릴 때 바꾸는 난수 값) 5개로 돌린 답 190개에서 센 수입니다.

검색 계획이 한국어 검색어와 영어 검색어를 함께 내면, 영어 질문도 한국어 문서를 찾을 수 있게 됩니다. 이번 이슈는 그렇게 되는지 잽니다.

확대 그림

두 번에 나눠 붙입니다. 먼저 요청 분석과 1단계 고리만 붙이고, 2단계의 생성·툴유즈 자리는 코드가 계획의 검색어로 지금 검색을 그대로 부릅니다. 그다음 도구 호출 검색을 붙여, 같은 자리를 모델이 검색 도구를 직접 부르는 방식으로 바꿉니다. 둘을 따로 재야 어느 쪽이 얼마나 바꿨는지 보입니다.

칸마다 받는 것과 넘기는 것

예는 모두 같은 질문 하나입니다. 질문 q03-en은 영어로 이트륨(yttrium)의 밀도를 묻고, 근거는 한국어 문서의 정보 상자에만 있습니다. 최소판은 이 질문에서 이름이 비슷한 이터븀(ytterbium) 문서를 가져와 5번 모두 답하지 못했습니다.

정할 것

재기 전에 정합니다. 결과를 보고 기준을 바꾸지 않기 위해서입니다. 노란 줄은 사용자가 정할 것입니다.

  1. 요청 분석과 1단계 생성을 모델 호출 한 번으로 할지, 두 번으로 나눌지AI가 안을 내고 사용자가 승인 · 한 번이면 빠르고, 두 번이면 요청 분석만 따로 기록·판정할 수 있습니다
  2. 검색 계획의 칸과 프롬프트 전문AI가 쓰고 사용자가 읽고 승인
  3. 1단계 저지먼트가 보는 것과 프롬프트 전문AI가 쓰고 사용자가 읽고 승인 · 판정 모델은 gemma3:4b로 정해져 있습니다
  4. 1단계 고리의 반복 한도와, 한도를 넘었을 때의 처리사용자 · 넘으면 마지막 계획으로 2단계에 갈지, 사람 검수 표시(사람이 확인해야 하는 답이라는 표시)를 붙일지
  5. 검색어 둘로 가져온 청크를 어떻게 합칠지AI가 안을 내고 사용자가 승인 · 최소판과 같은 청크 8개로 맞출지가 핵심입니다. 이것이 EVALUATION.md의 "첫 검색의 청크"의 뜻도 정합니다
  6. 재는 법과 판단 기준AI가 안을 내고 사용자가 승인 · 최소판은 질문을 그대로 검색해 씨앗 5번이 모두 같은 청크를 받았지만, 검색 계획은 생성 모델이 쓰므로 씨앗마다 검색어가 달라질 수 있습니다. 그래서 세는 단위(실행 190번마다 셀지, 질문 38개마다 셀지와 그때의 규칙), 몇 개가 늘어야 남길지, 답까지 돌릴지를 정합니다. 판정·고치기 전의 첫 계획과 마지막 계획을 둘 다 기록하면, 같은 실행으로 1단계 고리의 판정·고치기가 더하는 것도 잴 수 있습니다
  7. LangGraph와 ReAct를 고른 이유사용자 · 처음 계획 때 사용자가 정했고 이유 칸이 비어 있습니다. LangGraph 코드를 처음 쓰는 이번 이슈에서 채웁니다
  8. 검색 도구를 몇 개로 나눌지와 도구 호출 실행 기록의 칸AI가 안을 내고 사용자가 승인 · 도구 호출 검색을 붙이기 전에
