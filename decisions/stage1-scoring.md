# 결정: 1단계 채점

1단계(평가의 틀)에서 정한 것 가운데 답 하나를 판정하는 기준(환각, 정답 여부, 거절, 언어 혼동)과 지표를 계산하는 방법(Faithfulness, Precision@k, 관련성 비율), 채점 기록의 칸을 적는다. 새 결정은 표 아래에 추가하고, 바뀐 결정은 지우지 않고 새 줄로 적는다.

| 날짜 | 결정 | 정한 사람 | 이유 |
|---|---|---|---|
| 2026-10-12 | Faithfulness와 환각은 서로 다른 기준으로 잰다. Faithfulness는 검색된 청크가 뒷받침하는 주장의 비율이고 Agent-RAG만 잰다(Baseline은 해당 없음). 환각은 정답이나 근거 구절과 어긋나는 주장을 했거나 답이 없는 질문에 답을 지어낸 것이고 두 시스템 모두 잰다. | AI가 세 안을 내고 사용자가 선택 | Faithfulness는 RAG가 있어야 잴 수 있다. Baseline과 Agent-RAG의 환각을 비교하려면 두 시스템에 같은 기준이 있어야 한다. S5, S6을 봤다. |
| 2026-10-12 | 답마다 환각 여부(있음, 없음)와 정답 여부(정답, 일부만 답함, 거절함, 오답)를 따로 판정한다. 정답이 아니라고 환각으로 세지 않는다. 답은 맞지만 지어낸 내용이 섞인 답은 환각 비율에 넣는다. 답 없는 질문에서는 거절이 정답이다. Hallucination 비율은 환각 있음인 답의 수를 전체 질문 수로 나눈다. | 사용자 지적(오답이 곧 환각은 아니다, 환각을 먼저 가르고 나머지를 나눈다, 정답에 섞인 환각도 센다), AI가 두 안으로 정리하고 사용자가 선택 | 모른다고 한 답까지 환각으로 세면 환각이 아닌 것이 환각 비율에 들어간다. 답이 없을 때는 답이 없다고 하는 것이 맞는 대답이다. 한 답이 정답이면서 환각을 담을 수 있어 한 줄로 세우지 않는다. S1, S6을 봤다. |
| 2026-10-12 | 청크에 있는 내용으로 답했지만 물은 것에 답하지 않은 답은 환각으로 세지 않고 "오답, 환각 없음"으로 판정한다. 정답 여부에 값을 따로 만들지 않는다. 답이 질문과 관련 있는지를 재는 지표는 넣지 않는다. | 사용자가 축구 예시로 경우를 제기, AI가 두 안을 내고 사용자가 선택 | 지금은 과제가 요구하는 지표를 중심으로 본다. 이 경우는 두 판정의 조합으로 이미 구분된다. 문제가 보이면 개선 사항으로 다룬다. |
| 2026-10-12 | 환각 여부는 답의 주장을 정답·근거 구절에 비춰 맞음, 어긋남, 확인 불가로 판정하고, 어긋남만 환각으로 센다. 확인 불가인 주장이 있는 답의 수는 따로 적는다. 사용자가 웹이나 문서로 사실 여부를 찾아보지 않는다. | AI가 세 안을 내고 사용자가 선택. 확인 불가를 답의 수로 세는 것은 AI가 정함 | 확실히 틀린 것만 세어야 다시 판정해도 같은 결과가 나온다. 근거 구절에 없는 주장을 전부 환각으로 세면 Baseline은 사실을 말해도 환각이 된다. 하나씩 찾아보는 것은 7단계 0.5일에 들어가지 않는다. 대신 환각 비율이 실제보다 낮게 나올 수 있어 확인 불가의 수를 함께 적는다. 처음에 AI가 이 한계를 Baseline에만 해당한다고 적었으나, 답을 LLM이 쓰는 것은 Agent-RAG도 같다는 사용자 지적으로 두 시스템 모두로 고쳤다. |
| 2026-10-12 | 정답 여부는 정답에 꼭 들어가야 하는 필수 사실로 판정한다. 질문마다 정답을 필수 사실 목록으로 적는다. 칸 모양은 ③ 형식에서 정한다. | 사용자 지적(필수 사실을 정의해야 하는가), AI 정리 | 무엇이 다 들어 있어야 정답인지가 적혀 있어야 정답과 일부만 답함을 누가 판정해도 같게 가를 수 있다. |
| 2026-10-12 | Faithfulness를 계산할 때 사실 문장이 하나도 없는 최종 답은 계산에서 빼고, 뺀 답의 수를 함께 적는다. 주장은 유저가 최종으로 받은 답 안의 사실 문장으로 한다. | AI가 세 안을 내고 사용자가 선택 | 100%로 세면 답 있는 질문에 답을 내지 못할수록 Faithfulness가 올라간다. 0%로 세면 답 없는 질문에 맞게 없다고 한 답이 Faithfulness를 깎는다. 빠진 답이 어느 쪽인지는 정답 여부에서 보인다. S5를 봤다. |
| 2026-10-12 | 용어를 고정하고 `EVALUATION.md` 맨 위에 용어 표를 둔다. 거절은 시스템이 답을 내지 않은 행동만 가리키고, 답 없는 질문에서는 맞는 거절, 답 있는 질문에서는 틀린 거절이라 부른다. 정답 여부의 값 이름은 바꾸지 않는다. | 사용자 지적(비슷한 표현이 많아 헷갈린다, 답이 있는데 못 찾겠다고 한 것도 거절이다), AI가 안을 내고 사용자가 선택 | 시스템의 행동은 두 경우에 같고 다른 것은 그 행동이 옳았느냐뿐이다. 처음에 AI가 답 있는 질문의 거절을 "답 못함"으로 바꿔 부르자고 했으나, 그것도 거절이라는 사용자 지적으로 접었다. |
| 2026-10-12 | Precision@k는 검색된 청크 위에서 k개 가운데 근거 청크의 비율로 계산하고, 검색된 청크의 관련성 비율은 사용자가 청크를 하나씩 읽고 관련 있음·없음을 판정해서 낸다. 둘 다 Agent-RAG만 잰다. | AI가 두 안을 내고 사용자가 선택 | 과제가 두 지표를 따로 요구하는데 둘 다 근거 청크로 세면 거의 같은 숫자가 된다. 근거 청크는 아니지만 답에 쓸 수 있는 청크를 관련성 비율이 잡는다. 관련성 판정을 해 봐야 적어 두지 않은 근거 청크가 있는지도 드러난다(사용자 지적). 대신 사용자가 검색된 청크를 하나씩 읽어야 한다. S7을 봤다. |
| 2026-10-12 | 검색이 여러 번일 때 Precision@k와 관련성 비율은 최종 답을 쓸 때 입력으로 들어간 청크로 계산한다. 첫 검색은 Precision@k만 함께 적고 관련성 비율은 내지 않는다. 이 이유와 한계를 리포트에 적는다. | AI가 네 안을 내고 사용자가 선택. 리포트에 남기는 것은 사용자 지시 | 주 지표는 답을 만드는 데 실제로 쓰인 청크를 봐야 한다. 재검색 전후 비교에는 재검색 전의 값이 필요한데, Precision@k는 계산으로 나오고 관련성 비율은 사용자가 청크를 더 읽어야 한다. 그래서 전후 비교는 Precision@k로만 하게 된다. |
| 2026-10-12 | 답 없는 질문은 Precision@k와 관련성 비율의 계산에서 빼고, 답 있는 질문으로만 낸다. 대상 질문 수를 값 옆에 적는다. | AI가 두 안을 내고 사용자가 선택 | 답 없는 질문은 무엇을 검색해도 두 지표가 0이라 검색의 잘잘못을 말해 주지 않는다. 0으로 넣으면 값이 검색과 상관없이 내려간다. 답 없는 질문은 정답 여부와 환각 여부로 본다. |
| 2026-10-12 | Faithfulness와 관련성 비율의 최종 숫자는 분자를 전부 더해 분모를 전부 더한 값으로 나눈다. 답마다 비율을 내고 평균하지 않는다. 답마다의 분자와 분모는 원본 결과에 저장한다. | AI가 두 안을 내고 사용자가 선택 | 값이 분자·분모로 그대로 읽힌다. 답마다 평균하면 주장이 1개뿐인 답 하나가 값을 크게 흔든다. 답마다의 값이 원본에 남으므로 다른 방법으로도 다시 계산할 수 있다. 대신 긴 답이 값에 더 크게 들어간다. |
| 2026-10-12 | Faithfulness를 계산할 때 쓰는 주장 목록은 Agent-RAG 안의 판정 모델이 만들어 저장한 것을 쓰기로 잠정 정한다. 사용자는 주장마다 판정만 하고, 빠지거나 잘못 끊긴 주장은 고치고 기록한다. 사용자가 직접 끊는 방식과의 선택은 1단계 Codex 검토에서 다시 보고, 4단계에서 판정 모델의 설계가 정해질 때도 다시 본다. | 사용자가 정하기 어렵다고 해서 AI가 안 하나를 권했고 사용자가 승인 | 사용자가 최종 답 30개를 손으로 끊지 않아도 된다. 스텝퍼 7단계가 사람이 판정 모델과 같은 주장을 판정한다고 정해 두어 목록이 하나면 그대로 비교된다. 약점은 채점이 시스템 안의 모델이 만든 목록에 기대는 것이고, 원문을 나란히 보고 고친 수를 적는 규칙으로 줄인다. |
| 2026-10-12 | Precision@k의 분모는 최종 답에 실제로 들어간 청크의 수로 한다. 분모가 k와 다르면 리포트에 밝힌다. | AI가 두 안을 내고 사용자가 선택 | 재검색 때 이전 청크를 살릴지는 4단계에서 정해지는데, 어느 방식이 되어도 그대로 계산된다. 관련성 비율과 같은 청크를 같은 분모로 본다. 항상 k로 하면 합쳐진 청크의 순위를 매기는 규칙이 따로 필요하다. |
| 2026-10-12 | 정답 여부는 답 있는 질문과 답 없는 질문을 나눠서 낸다. 답 있는 질문은 네 값의 개수와 정답 비율(정답 수 ÷ 답 있는 질문 수), 답 없는 질문은 맞는 거절 비율(맞는 거절 수 ÷ 답 없는 질문 수)이다. 합친 숫자는 내지 않는다. | AI가 두 안을 내고 사용자가 선택 | 합치면 무엇을 물어도 거절하는 시스템이 6/30을 얻고 그것이 실력인지 거절 덕인지 알 수 없다. 나누면 전부 거절하는 시스템과 전부 지어내는 시스템이 각각 드러난다. |
| 2026-10-12 | 거절의 기준을 "주장이 없다"에서 "물은 것에 대한 답을 내지 않았다"로 바꾼다. 거절에 붙은 설명은 보통의 주장처럼 채점한다. 설명이 틀리면 환각 있음이고, Agent-RAG의 Faithfulness 계산에도 넣는다. 주장이 하나도 없는 거절만 Faithfulness에서 뺀다. 앞의 용어 결정과 Faithfulness 예외 결정을 고친 것이다. | AI가 두 안을 내고 사용자가 선택 | 전제가 틀린 질문의 맞는 대답("그런 것은 없다. 실제로는 이렇다")에는 주장이 들어가서 앞의 정의로는 거절인지 정해지지 않았다. 설명을 채점하지 않으면 거절하면서 틀린 설명을 지어낸 답이 환각 없음이 된다. |
| 2026-10-12 | 질문과 다른 언어로 답했어도 내용이 맞으면 정답으로 판정하고, 언어 혼동은 답마다 있음·없음으로 따로 판정한다. 진행하다가 오답으로 봐야 한다고 판단되면 그때 보완한다. | AI가 두 안을 내고 사용자가 선택 | 내용이 틀린 것은 아니다. 오답으로 판정하면 정답 비율이 내려갔을 때 내용 때문인지 언어 때문인지 숫자만으로 확인하기 어렵다. 따로 판정하면 과제의 오류 유형인 언어 혼동의 빈도가 그대로 나온다. |
| 2026-10-12 | 사용자가 채점할 때 적는 채점 기록의 칸을 1단계 ③에서 정한다. ④에서 정한 판정을 칸으로 옮긴 것이고, 개발용과 최종 평가용에 같은 형식을 쓴다. 시스템이 저장하는 실행 기록의 구조는 4단계에서 정한다. 질문 파일의 청크 이름은 사용자가 적지 않고 코드가 근거 구절을 청크에서 찾아 채운다. | AI 제안, 사용자 승인 | 질문 파일만으로는 정답 비율, Hallucination 비율, Faithfulness, 관련성 비율을 계산할 값이 적힐 곳이 없었다. 1단계의 검토 초점이 "형식의 칸으로 모든 지표를 계산할 수 있는가"이다. 판정의 종류는 ④에서 이미 정했으므로 새로 정한 내용은 없다. |
