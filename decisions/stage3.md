# 결정: 3단계 질문

3단계(질문)에서 정한 것을 적는다. 질문을 대조하는 방법, 질문 수의 배분, 질문을 만드는 규칙, 형식 검사, 최종 평가용의 보관이다. 새 결정은 표 아래에 추가하고, 바뀐 결정은 지우지 않고 새 줄로 적는다.

| 날짜 | 결정 | 정한 사람 | 이유 |
|---|---|---|---|
| 2026-10-15 | **영어 근거 구절이 정답을 말하는지는 사용자가 번역기(예: 파파고)에 근거 구절을 직접 붙여 넣어 옮긴 글로 대조한다.** AI가 옮긴 글로 대조하지 않는다. 근거 구절이 여러 개이면 구절마다 넣는다. 구절은 질문 목록에서 복사하며, 원문에 글자 그대로 있는지는 형식 검사 스크립트(3단계 ④)가 본다. 이 결정은 "근거 구절이 정답을 말하는가"에만 쓴다. 같은 문서 안의 다른 값은 숫자·이름을 `Cmd+F`로 찾고, 영어 근거 질문의 반대 언어 문서(한국어)는 사용자가 직접 읽는다. 유형 판단(단일 사실과 표현 불일치를 가르는 것)에는 번역기를 쓰지 않는다는 `EVALUATION.md` ①의 규칙은 그대로다. 개발용 질문을 실제로 대조해 보며 문제가 나오면 보완한다. | 사용자(AI가 두 안을 내고 나를 추천. 사용자의 말: "그렇게 하자. 실제로 해보면서 문제가 있으면 그때 다시 보완하거나 해야할것 같아") | 사용자는 영어를 읽지 못한다(2026-10-13). AI가 후보를 만들고 번역도 하면 같은 잘못 읽기가 두 번 나와 서로 덮는다. 예로 든 원문 `wiki-en-jeonju.md`의 "Jeongdong Catholic Church was built on 1908–1914 ... on the site of the Korean Catholic martyrs in 1791 and 1801"에서 지은 해(1908–1914)와 순교한 해(1791, 1801)를 혼동한 후보는, 같은 혼동으로 옮긴 글과 맞아떨어진다. 번역기는 후보를 만든 AI와 따로 읽으므로 같은 자리에서 같은 방식으로 틀릴 가능성이 낮다. 유형 판단에 번역기를 쓰지 않는 까닭은 번역기가 고른 낱말이 판정을 정하기 때문이며(예: "넓이"를 `area`로 옮기면 단일 사실, `size`로 옮기면 표현 불일치), 근거 대조는 뜻만 보므로 번역의 낱말 선택에 흔들리지 않는다. 한계: 번역기도 틀릴 수 있다. 질문마다 사용자가 붙여 넣는 손이 든다. |
