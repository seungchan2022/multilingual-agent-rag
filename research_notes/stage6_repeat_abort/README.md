# Baseline이 되풀이로 끊긴 사례 (이슈 #12, 2026-10-24)

6단계 "모델의 한계"를 볼 때 쓰려고, 다시 만들기 어려운 것을 여기 모아 둔다. 판단은 `decisions/judgments.md` 2026-10-24, 처리 규칙은 `decisions/stage6.md` 2026-10-24 "되풀이로 끊긴 답" 줄.

## 무슨 일이었나

- Baseline(문서 없이 답) 실행에서 씨앗 5, 질문 q04-ko(툴륨 직육면체의 질량, 정답 0.5592 kg)에 모델 qwen3:8b가 answer에 "0.000…"을 끝없이 썼고, Ollama가 `prediction aborted, token repeat limit reached`로 생성을 끊었다.
- reason에서 계산을 하지 않고 방법만 말한 뒤 answer를 "0."으로 시작했다. 재현은 모두 같은 지시문·생성 설정·JSON 모드로 했으므로, 이것들이 되풀이에 기여했는지는 모른다(Codex 1차 지적 2). 밀도도 9.90 g/cm³로 틀렸다(문서 값 9.32).
- 380번 본 실행(`data/minimal/generation/runs_baseline.jsonl`)에서도 같은 요청이 끊겼고, 그 줄에 끊기기 전 글(270자)이 `output`, 이유가 `abort_reason`으로 남아 있다. 최소판(청크를 넣음)에서는 끊긴 답이 없었다.

## 재현 조건 (다시 해 보려면)

- 같은 순서: 몸풀기 → 씨앗 1~5 × 질문 38개(파일 순서), 한 번에 하나씩. 159번째가 이 요청이다.
- **앞서 캐시에 남은 요청이 실제 실행과 같아야 한다.** 모델을 내렸다가 시작하면(재현 ②, `target_cold.json`) 앞 158개가 글자까지 같고 같은 곳에서 끊겼다. 셋째 실행(`runs_baseline.aborted-3.jsonl`)은 모델을 다시 올리지 않고 시작했지만, 직전에 멈춘 실행이 같은 몸풀기와 같은 첫 질문만 보낸 상태라 역시 158개가 같고 끊겼다. 반대로 재현 ①(`target_warm.json`)은 직전에 다른 요청 둘(q03-en·q04-ko 씨앗 5)을 따로 보낸 뒤 시작해 158개 중 155개만 같았고 이 요청은 정상으로 답했다(0.495 kg). 그래서 글을 가른 것은 "모델을 막 올렸는가"보다 "캐시에 다른 요청이 남았는가"로 읽는다(Ollama 로그의 모델 올림 시각으로 확인, 원인 자체는 추론). 모델을 내렸다가 시작하면 늘 같은 상태에서 시작한다.
- 같은 환경: `environment.txt`(Ollama 0.35.1, qwen3:8b digest `500a1f06…`, Apple M3 Pro). Ollama나 모델 파일이 바뀌면 재현되지 않을 수 있다. Ollama 앱은 스스로 업데이트할 수 있으므로, 다시 해 보려면 먼저 판을 확인한다.
- 생성 설정: `src/minimal/generate.py`(커밋 `c5a4ae0`)의 `request_body`.

## 뒤에 볼 것 (모델의 한계에서)

- 로그에는 10-18과 10-20에도 HTTP 500이 여러 번 있다. 10-20의 것은 도시 도메인 실험(`research_notes/stage2_stem_select/city_v1/results/run.log`, `run_c010.log`)에서 난 것으로, 그 실험 프로그램은 오류 내용(응답 본문)을 남기지 않아 같은 되풀이였는지 가를 수 없다. 10-18의 것은 저장소 밖의 멘토 숙제 실험이다. 도시 도메인은 버렸고 그 실행 상태를 다시 만들 수 없어 확인할 방법이 없다(한계).
