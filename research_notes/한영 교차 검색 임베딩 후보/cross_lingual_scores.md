# Published Korean↔English cross-lingual retrieval scores of open-weight multilingual embedding models (2025–2026 focus)

Research date: 2026-10-23. All numbers below were read from the cited source (paper text, model card, or the raw JSON result file). Nothing was estimated or rounded beyond the two decimals shown in the source/JSON (MTEB JSON stores 0–1 fractions; they are shown here ×100).

Direction notation used throughout: **"KO q→EN doc"** = Korean query, English documents (this is the project's "Korean question, answer only in an English document" case). **"EN q→KO doc"** = English query, Korean documents.

Provenance labels used: **[SELF]** = reported by the model's own authors; **[INDEP]** = reported by a party that did not build the model; **[MTEB-REPO]** = raw result file in the public MTEB results repository (files are added either by MTEB maintainers or by model authors via pull request; who ran each file is not recorded in the file; for the key rows, the committer is listed under Table A and used to mark them [SELF] or [INDEP]).

## Which benchmarks report KO→EN and/or EN→KO retrieval, and what are the exact numbers?

### Takeaway
Four public sources give Korean↔English cross-lingual retrieval numbers for open models: MMTEB **BelebeleRetrieval** (both directions, nDCG@10, 50+ relevant models), MMTEB **XPQARetrieval** (both directions, product-QA, nDCG@10), **Jang et al. 2025/2026** (Belebele + StrategyQA, both directions, nDCG@10, 4 base models incl. gte-multilingual-base), and **MKQA** (KO q→EN Wikipedia/NQ passages, Recall@20/100, in the BGE-M3 and Conan-v2 papers). No single source ranks all three assignment models together; pairwise, Jang et al. has bge-m3 > gte-multilingual-base on all four KO↔EN columns, MTEB Belebele has bge-m3 > paraphrase-multilingual-MiniLM-L12-v2, and MTEB xPQA has gte-multilingual-base > MiniLM. Important limitation: every one of these cross-lingual sets uses a corpus in **one** language only (no same-language distractors), and Belebele passages are parallel FLORES translations where top models score in the high 90s — so these numbers measure KO↔EN alignment and are an upper bound for a mixed KO+EN index like ours.

### Cited Findings

**How direction was verified for the MMTEB tasks (needed to read every MTEB number below correctly)**
- In the MTEB `BelebeleRetrieval` task code, the subset name `X-Y` loads the **corpus from X and the questions from Y** (`lang_corpus, lang_question = languages[0], languages[1]`). So subset `kor_Hang-eng_Latn` = Korean passages + English questions = **EN q→KO doc**, and `eng_Latn-kor_Hang` = **KO q→EN doc**. Main score is `ndcg_at_10`. — [mteb belebele_retrieval.py (main branch, read 2026-10-23)](https://github.com/embeddings-benchmark/mteb/blob/main/mteb/tasks/retrieval/multilingual/belebele_retrieval.py)
- For `XPQARetrieval` the same convention holds: I read sample rows of the HF dataset. Subset `eng-kor` has Korean queries (e.g. "원산지 어디인가요?") and English corpus ("it contains a large circumference of track…") = **KO q→EN doc**; subset `kor-eng` has English queries ("can i buy it at 220v?") and Korean corpus = **EN q→KO doc**. Sizes: eng-kor 654 queries / 1,169 docs; kor-eng 614 queries / 889 docs. — [HF datasets-server, mteb/XPQARetrieval eng-kor-queries](https://datasets-server.huggingface.co/rows?dataset=mteb/XPQARetrieval&config=eng-kor-queries&split=test&offset=0&length=2); [kor-eng-queries](https://datasets-server.huggingface.co/rows?dataset=mteb/XPQARetrieval&config=kor-eng-queries&split=test&offset=0&length=2); task code [xpqa_retrieval.py](https://github.com/embeddings-benchmark/mteb/blob/main/mteb/tasks/retrieval/multilingual/xpqa_retrieval.py)
- Cross-check: Jang et al. Table 1 (labelled "en-ko" = English query, Korean passage) gives mE5-base 82.28 / 77.52 and mE5-large 92.03 / 86.45 for Belebele en-ko / ko-en — identical to the MTEB files' `kor_Hang-eng_Latn` / `eng_Latn-kor_Hang` values; bge-m3 is 90.37 / 88.36 in Jang vs 90.32 / 88.32 in the MTEB file. This confirms the direction mapping, but also means Jang's Belebele numbers are very likely the same evaluation as MTEB's, not a separate confirmation. — [Jang et al., arXiv 2507.08480](https://arxiv.org/html/2507.08480); MTEB files linked in the table in the next section.
- Comparability caveat (from the raw files): Belebele result files in the repo use two dataset revisions (43 of the files I tabulated use `75b3993`, 10 use `979a211`); xPQA files use `c99d599` (14) or `fc4624b` (11); mteb library versions range 1.12.75 → 2.26.16. The revision of each row is printed in the table. — [MTEB results repo at commit 0acf39c (2026-10-22)](https://github.com/embeddings-benchmark/results/tree/0acf39c2bd00210e746b163fdcf215954f281af0)

### Inferences
- Pairwise, per source (no source has all three): Jang et al. bge-m3 > gte-multilingual-base (Belebele KO q→EN doc 88.36 vs 85.66; StrategyQA KO q→EN doc 71.65 vs 64.38); MTEB Belebele bge-m3 > MiniLM (KO q→EN doc 88.32 vs 70.38, a gap of 17.94); MTEB xPQA gte-multilingual-base > MiniLM (KO q→EN doc 31.77 vs 21.51). The order bge-m3 > gte > MiniLM is therefore an inference that chains two sources, not a measured three-way ranking.
- KO q→EN doc is harder than EN q→KO doc for almost every model in every source (e.g., StrategyQA bge-m3 71.65 vs 81.24). For the project, the "Korean question, English-only answer" half of the hard set is likely the weaker half.
- Belebele is near ceiling for strong models (≥ 95 for several), so differences of 1–2 points there are less informative than StrategyQA or xPQA differences.

### Gaps
- XOR-TyDi QA (XOR-Retrieve, which has Korean queries over English Wikipedia) was not checked for 2025–2026 model numbers.
- MIRACL is monolingual (ko→ko) only; I found no "cross-lingual MIRACL" variant with Korean numbers.
- mMARCO: Korean coverage and any KO↔EN cross-lingual run not verified.
- MTEB `MKQARetrieval` result files exist for ~40 models, but I did not verify whether its corpus is English (cross-lingual) or same-language, so I report no numbers from it.
- No benchmark found that tests KO↔EN retrieval over infoboxes, tables, or numeric content (the project's main content type).
- The Korean MTEB v2 benchmark's original version reportedly has KO q→EN corpus and EN q→KO corpus subsets, but the KURE-v2 card reports only the ko-ko results. — [KURE-v2 model card](https://huggingface.co/nlpai-lab/KURE-v2)

## Candidate models: per-model KO↔EN numbers

### Takeaway
MMTEB BelebeleRetrieval gives both KO↔EN directions for nearly every candidate except gte-multilingual-base and jina-embeddings-v4. Among free, open-weight dense single-vector models under ~600M params, the highest Belebele KO q→EN doc scores are EmbeddingGemma-300m (92.92), jina-embeddings-v5-text-small/nano (91.78/91.75, but CC-BY-NC), EmbeddingGemma-2 (91.40, released 2026-10-06), BGE-m3-ko (91.24), PIXIE-Rune-v1.5 (91.02), KURE-v1 (90.58), pplx-embed-v1-0.6b (90.52), KoE5 (90.39) — vs bge-m3 88.32. The sparse KURE-Sparse-base (593M) scores 94.73, but it is a different retrieval type. Larger models (Qwen3-Embedding-4B/8B, F2LLM-v2-4B/8B, pplx-4b, harrier-27b, comsat-ko-8b) score higher but are 4–27B params.

## Is there evidence of "language bias" in mixed-language corpora, and which models suffer less?

### Takeaway
Yes, several 2025–2026 papers document it, but **I found no mixed-index benchmark that includes Korean with a comparison across embedding models**. The best multi-model evidence (Ghorbanpour et al., Oct 2026; 10 languages, no Korean) shows mE5-base/large and e5-mistral are crowded out by same-language documents, while bge-m3 and Qwen3-Embedding-8B keep the highest mixed-index scores. The only Korean evidence at the retriever stage (Park & Lee 2025) uses bge-m3 alone and shows Korean queries prefer English documents slightly more than Korean ones, while English queries strongly prefer English.

### Cited Findings

Korean NOT included** (Belebele: en, es, fr, it, pt, ru, ar, hi, zh, ja; XQuAD: en, es, ru, ar, hi, zh). Numbers checked in the arXiv HTML tables. — [arXiv 2610.18526](https://arxiv.org/html/2610.18526)

- Same models in a **bilingual** pool (query language vs one foreign language): Recall@20 averages 97.8 (mE5-large), 92.8 (Qwen3-0.6B), 97.6 (Qwen3-8B). The authors conclude the failure is "interference under competition, not an inability to represent foreign documents."

Retriever = bge-m3 only; MLRS (MultiLingualRankShift: how much non-query-language docs rise in rank when translated into a target language; higher = stronger preference for that target language).** — [arXiv 2502.11175v4](https://arxiv.org/pdf/2502.11175v4)

**Goworek, Macmillan-Scott, Özyiğit, "What Drives Cross-lingual Ranking?" (Alan Turing Institute; arXiv 2511.19324v1, 24 Nov 2025). 27 languages incl. Abstract: language identity "can inflate similarity for same-language pairs and crowd out relevant evidence written in other languages." — [ACL Anthology 2026.acl-long.1685](https://aclanthology.org/2026.acl-long.1685.pdf)

**Wang et al., "All Languages Matter: Understanding and Mitigating Language Bias in Multilingual RAG" (CAS / Ant Group; arXiv 2604.20199v1, 22 Apr 2026). Korean included; the bias studied is at the RERANKER stage (bge-m3 retrieves top-50 from a 13-language Wikipedia pool).** With BGE-Reranker-V2-M3, "around 60% of candidate documents are concentrated in English and the query language." Korean answer quality (character 3-gram recall, Llama-3.1-8B generator): BGE reranker 25.5, Qwen3-Reranker-0.6B 23.3, oracle language selection 41.0 (Qwen2.5-7B generator: 26.5 / 24.7 / 38.9). — [arXiv 2604.20199](https://arxiv.org/pdf/2604.20199)

### Inferences
- From Ghorbanpour Table 3, the mE5 family and e5-mistral are displaced mostly by non-relevant same-language documents (77.7–91.6%), i.e. the "prefers same-language document" failure; bge-m3 is displaced mostly by documents in other foreign languages (72.8%), not the query language. How this carries over to a two-language KO+EN index is untested.
- Setup mismatch: Ghorbanpour's mixed index is parallel and "all-gold" (every language's copy of a passage counts as relevant), whereas in the project the answer exists in one language only. The finding that mE5 lifts non-relevant same-language documents above relevant foreign ones transfers; the absolute nDCG values do not.
- The LangSAE and Ghorbanpour mixed-pool numbers are not comparable with each other (different pool construction and relevance definition), which is why mE5-large is 0.5359 nDCG@20 on Belebele in one and 73.7 in the other.
- Park & Lee's numbers suggest, for bge-m3, that English queries strongly favour English documents (56.03 vs 33.02), while Korean queries slightly favour English over Korean documents (43.49 vs 41.15). For the project's "English question, answer only in a Korean document" half, this points to English distractors as the main risk. Note these are MLRS rank-shift values, not retrieval accuracy.
- Combined with the "KO→KO minus KO→EN" proxy in Table A, multilingual-e5 base/small, snowflake-arctic-embed-m-v2.0 and nomic-embed-text-v2-moe are the candidates most likely to suffer same-language preference with Korean queries; bge-m3, jina-v3/v5, EmbeddingGemma, Qwen3-4B/8B and F2LLM-v2 ≥0.6B the least (single-language-corpus evidence only).

### Gaps
- No Korean mixed-language-index retrieval benchmark with several embedding models was found; the project will have to measure this itself.
- Ghorbanpour reports Recall/nDCG in a mixed index of 6–10 languages; the effect in a two-language (KO+EN) index of 20 Wikipedia articles is untested.
- A job-retrieval paper (arXiv 2502.03220) was reported in search snippets to find bge-m3 biased toward the query language; I did not read it, so no numbers are given.

## Do any papers find that Korean-specialized fine-tunes lose KO↔EN cross-lingual ability?

### Takeaway
No paper tests this directly. In MMTEB Belebele, most Korean fine-tunes of multilingual models **gained** on both KO↔EN directions versus their base (KURE-v1, BGE-m3-ko, arctic-l-v2.0-ko, mE5-small-ko, KoE5; bases confirmed from the fine-tunes' Hugging Face cards); one (upskyy/bge-m3-korean) **lost** on all three Korean subsets including KO→KO, which looks like general degradation rather than a cross-lingual-specific loss. Evidence is Belebele-only and no paper checks a harder KO↔EN set.
