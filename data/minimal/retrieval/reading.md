# 검색 비교 결과를 읽은 내용

이슈 #10, 2026-10-23. 수치는 모두 `results.jsonl`(조합 8개 × 질문 38개 = 304줄)과 청크 묶음 파일에서 계산했다. 표는 `summary.md`에 있다. 기준(✔, 비김 2개, 고르는 순서)은 결과를 보기 전에 커밋했다(`b79e175`).

## 고른 조합

**크기 128 + 제목 붙임 + bge-m3(k = 8)**, 전체 ✔ 31/38.

고른 과정:
- 가장 많은 것은 256 + 제목 붙임 + bge-m3의 32다. 30 이상인 세 조합이 비겼다: 256 제목 bge 32, 128 제목 bge 31, 128 제목 gte 30.
- 1칸(다른 언어 16개 ✔): bge 둘이 11/16, gte가 8/16이라 bge 둘이 남았다.
- 2칸(gte인가)과 3칸(제목을 붙이지 않았는가)은 둘이 같았다.
- 4칸(작은 크기)에서 128이 골라졌다.

## 결과에서 읽은 것

1. **제목을 붙이면 네 쌍 모두 ✔가 늘었다.**
   - 네 쌍: bge 128은 21 → 31, bge 256은 23 → 32, gte 128은 26 → 30, gte 256은 18 → 24.
   - q05~q08(한국어·영어 8개)은 제목을 붙인 조합에서만 맞았다. 모두 원소 정보 상자의 밀도 줄이 근거인 질문이다.
   - 정보 상자 묶음에는 원소 이름이 없고 문서 제목에만 있다(`decisions/stage4.md` 2026-10-22 정보 상자 줄 ㉡). 제목을 붙이자 어느 원소의 묶음인지가 청크 글에 들어갔다.
   - 반대로 제목을 붙이지 않은 조합에서만 맞은 질문은 q12-en 하나다.
2. **청크 통계와 이어지는 것: 크기 128의 표 조각은 머리글 + 행 하나이고, 그 행을 가려내는 힘은 모델마다 달랐다.**
   - 128 + 제목 붙임 묶음에서 동위 원소 표의 조각은 339개다. 그중 334개가 한도를 넘었다(머리글 + 행 하나가 128토큰보다 길다). 한도를 넘긴 청크 352개의 거의 전부가 이 조각이다(`summary.md` "청크 묶음").
   - 조각끼리는 머리글이 같고 행 하나만 달라 서로 비슷하다. 실제로 두 모델 모두 상위 8개의 거리가 좁게 몰렸다(q11-ko: bge 0.2905~0.2992, 폭 0.0087 / gte 0.2174~0.2313, 폭 0.0139).
   - 그런데 결과는 갈렸다.
     - gte는 q11-ko, q12-ko, q13-en, q14-en에서 정답 행의 조각을 1등에 놓았다.
     - bge는 넷 다 놓쳤다.
     - 그러니 거리가 몰리는 것(청크 모양)만으로는 놓친 까닭이 설명되지 않는다. 같은 조각들 가운데 질문이 가리키는 행(예: ¹⁴⁴ᵐ⁴Tb)을 가려내는 데서 bge가 gte보다 약했다고 본다. 이것은 네 질문에서 본 추론이고, 까닭을 따로 재지는 않았다.
   - 영어 질문 → 한국어 네오디뮴 표(q13-en, q14-en)에서는 차이가 더 크다.
     - bge는 상위 8개가 모두 영어 문서(Europium, Praseodymium 등)였다. 한국어 표에 닿지도 못했다.
     - gte는 상위 8개가 모두 한국어 네오디뮴 표였다.
   - 표 질문 10개(q10~q14 한국어·영어, 터븀·네오디뮴 표)의 ✔:

     | 조합 | ✔ |
     |---|---|
     | bge 128 제목 없음 | 4 |
     | bge 128 제목 붙임(고른 조합) | 5 |
     | bge 256 제목 없음 | 6 |
     | bge 256 제목 붙임 | 6 |
     | gte 128 제목 없음 | 9 |
     | gte 128 제목 붙임 | 9 |
     | gte 256 제목 없음 | 8 |
     | gte 256 제목 붙임 | 6 |

   - 고른 조합은 표 질문에서 약하다. 특히 영어 질문 → 한국어 네오디뮴 표(q13-en, q14-en)는 bge 네 조합이 모두 놓쳤고, gte 네 조합은 모두 맞혔다.
3. **모든 조합이 놓친 질문은 q03-en과 q09-en이다.**
   - 둘 다 영어 질문이고, 근거는 한국어 문서(이트륨, 어븀)의 정보 상자 밀도 줄이다.
   - 고른 조합은 이름이 비슷한 원소의 영어 문서(Ytterbium, Isotopes of yttrium)를 가져왔다.
   - 같은 원소의 한국어 질문 q03-ko는 맞았다.
   - 질문 언어와 다른 언어의 문서에서 찾는 쪽이 가장 약하다는 4단계의 예상(고르는 순서 1칸의 이유)과 같은 모양이다.
4. **실제로 가져온 양은 명목 예산 1,024토큰과 다르다.**
   - 고른 조합은 질문마다 평균 957.7, 최소 770, 최대 1,296토큰을 가져왔다.
   - 한도를 넘긴 표 조각과 붙인 제목 줄 때문이다.
   - 4단계에서 "같은 명목 예산으로 견줬다"고 적기로 한 것(`decisions/stage4.md` "Codex 1차 검토" 줄 ㉦)과 같다.

5. **4단계 인계에 적힌 전제 하나는 더는 맞지 않다.**
   - 4단계 인계는 "터븀 표는 128과 256의 조각이 같아 q10~q12에서 크기 차이가 드러나지 않는다"고 적었다.
   - 들뜬 상태 행 규칙(`decisions/stage4.md` 2026-10-23 "들뜬 상태 행의 값에 이름을 붙이고" 줄)으로 둘째 머리글 줄이 빠지고 행이 짧아졌다. 그래서 지금은 256 조각에 행이 여럿 들고, 128 조각은 여전히 행 하나다.
   - 실제로 q12-ko는 bge 256 두 조합에서 맞고 bge 128 두 조합에서 놓쳤다.

6. **근거 줄이 여러 청크로 잘린 경우의 영향**(`STEPPER.md` 5단계 검토 초점 "근거 구절이 잘린 경우의 영향")
   - 고른 묶음(128 제목 붙임)에서 근거 줄이 둘 이상의 청크에 나뉜 질문은 5쌍 10개다. 표 머리글이 되풀이되어 생기는 것은 세지 않았다.
     - q02·q04: 이터븀 한국어 83줄·영어 92줄이 각각 2조각.
     - q16: 중성자 포획 치료 129줄이 2조각.
     - q18: 같은 문서 125줄이 3조각.
     - q19: 같은 문서 159줄이 8조각.
   - 어느 경우든 정답 값(`value_text`)이 든 조각이 적어도 하나 있다. q18은 3조각 중 2개, 나머지는 1개다.
   - 고른 조합은 이 10개를 모두 맞혔다.
   - 크기 256 묶음에서는 q19만 3조각으로 나뉜다.
   - 이 38개에서는 잘림 때문에 놓친 질문이 없다. 다만 정답 값이 없는 조각도 같은 줄 번호를 갖는다. 그래서 ✔에 `value_text`를 함께 보는 규칙(`decisions/stage4.md` "Codex 1차 검토" 줄 ㉤)이 이런 조각을 ✔에서 빼는 데 쓰였다.

## 한계와 다음에 볼 것

- 질문이 38개라 1~2개 차이는 우연일 수 있다. 그래서 2개까지를 비김으로 정했다.
- 표 질문 10개에서 gte가 앞선 것(9 대 5)은 고르는 기준에 들지 않는다. 기준은 전체 ✔와 다른 언어 16개다.
- 이 결과를 보고 기준을 바꾸지 않았다(CLAUDE.md 3번).
- 7단계 전 개발용 질문으로 값을 다시 확정할 때(`DECISIONS.md` 미정 목록 "128이면 청크 8개가 과한지" 줄) 이 차이가 이어지는지 본다. 개발용 질문에는 표 질문이 따로 들어 있다.
- 6단계에서 고른 조합으로 답을 만들 때, 표 질문(q10~q14)은 검색에서 놓친 것이 답의 오답으로 이어지는지 실행 기록으로 본다.
