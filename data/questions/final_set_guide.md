# 최종 평가셋을 만드는 순서와 대처 (사용자용)

최종 평가용 질문은 Claude(Opus), 서브에이전트, Codex가 7단계 전에 보면 안 된다. 그래서 이 작업은 사용자가 웹 임시 채팅에서 혼자 한다. 이 글은 그때 따라갈 순서와, 문제가 생겼을 때 할 일을 적은 것이다. 웹 AI에게 주는 글은 `final_set_instructions.md`에 있다.

`<...>`로 적은 곳은 3단계에서 채운다. 이 글의 대처는 해 보기 전에 떠올린 것이라, 개발용 질문을 만들 때와 연습 때 드러난 문제로 고친다.

## 순서

1. **개발용 질문을 먼저 끝낸다.** Claude가 후보를 내고 사용자가 원문과 대조한다. 규칙이 실제 문서에서 통하지 않는 곳이 드러나면 `EVALUATION.md`와 지시서를 함께 고친다.
2. **웹에서 연습을 한 번 한다.** 문서 두세 개만 올리고 지시서로 후보를 몇 개 받아 본다. 이때 개발용 질문이 이미 물은 사실로만 만들게 한다(개발용 질문의 질문 문장을 붙이고 "아래 질문들이 묻는 사실로만 만든다"고 적는다). 아직 아무도 묻지 않은 사실을 연습에서 쓰면 본 작업에 쓸 사실이 그만큼 줄기 때문이다. 연습에서 받은 후보는 최종 평가용에 쓰지 않는다. 막힌 곳과 지시서가 통하지 않은 곳을 Claude에게 알리고(질문 내용은 빼고) 지시서와 이 글을 고친다.
3. **본 작업을 한다.** 새 임시 채팅에 지시서, 문서 목록, 원문을 올리고 후보 60개를 받는다. 개발용 질문과 연습 질문의 질문 문장을 함께 붙여 겹치지 않게 한다.
4. **후보를 하나씩 원문과 대조한다.** 아래 "대조할 것"을 따른다.
5. **개수표대로 30개를 고른다.** 칸마다 필요한 수(`EVALUATION.md` ②)만 남긴다. 남긴 것의 `id`를 후보 번호(`c-`)의 순서대로 `final-001`부터 다시 붙인다. 번호는 7단계에서 심화 분석할 사례를 고르는 데 쓰이므로 결과를 보기 전인 이때 붙이고 그 뒤에 바꾸지 않는다.
6. **형식 검사 스크립트를 돌린다.** `<3단계에서 만든 뒤 명령을 적는다>` 스크립트는 질문 내용을 보여 주지 않고 통과 여부와, 틀렸으면 어느 항목의 어느 칸인지만 알려 준다.
7. **개발용 질문과 겹치는지 본다.** 같은 사실을 묻는 질문이 있으면 최종 평가용 쪽을 여분의 후보로 바꾼다. 겹친 수와 바꾼 수만 기록한다.
8. **프로젝트 폴더 밖에 저장하고 해시를 계산한다.** 저장할 곳: `<3단계에서 정한다>`. 해시 명령: `shasum -a 256 <파일>`. 나온 값만 Claude에게 알린다. 파일의 내용은 알리지 않는다.

## 대조할 것

후보마다 아래를 본다. 하나라도 걸리면 고치거나 버린다. 여분이 있으므로 애매하면 버린다.

답 있는 질문:

- `passage`가 원문에 글자 그대로 있는가. 원문 파일에서 찾기로 확인한다.
- `passage`만 읽고 정답이 나오는가. 조건과 단위까지 들어 있는가.
- 정답이 하나로 정해지는가.
- `required_facts`가 정답에 꼭 필요한 사실을 빠짐없이, 군더더기 없이 담는가.
- 유형이 맞는가. 두 유형에 걸치지 않는가.
- 반대 언어 문서에 같은 사실이 없는가. 그 사실의 핵심 낱말을 반대 언어로 바꿔 반대 언어 문서 전체에서 찾아본다. AI의 확인 메모는 참고만 하고 직접 찾아본다.
- 표가 근거이면 머리글 행과 해당 행이 둘 다 적혀 있는가.

답 없는 질문:

- 문서 전체에서 한국어 표현과 영어 표현으로 찾아봐도 답이 없는가.
- 문서를 보지 않고 일반 지식으로도 답할 수 없는가. 세상에 실제로 답이 있는 질문이면 버린다.
- 전제가 너무 뻔하게 틀리지 않았는가.
- `rebuttal`이 있으면 원문에 글자 그대로 있는가.

## 문제가 생겼을 때

| 문제 | 할 일 |
|---|---|
| 문서가 많아 한 번에 올라가지 않는다 | 지시서의 "나눠서 요청할 때"를 쓴다. 이때 반대 언어 문서의 확인은 AI가 할 수 없으므로 사용자가 전부 한다 |
| AI가 개수를 못 채웠다고 한다 | 모자란 칸과 이유를 적어 둔다. "한 칸만 다시 요청할 때"로 한 번 더 요청한다. 그래도 안 되면 그 칸은 코퍼스에 재료가 모자란 것이므로 멈추고 Claude에게 칸과 모자란 수만 알린다. 개수표나 문서를 바꿀지는 그때 정한다 |
| AI가 형식을 틀리게 낸다 | 형식 검사 스크립트의 메시지를 AI에게 붙여 고치게 한다 |
| `passage`가 원문과 글자가 다르다 | 원문에서 직접 복사해 고친다. 원문에 그런 구절이 없으면 그 후보를 버린다 |
| 반대 언어 문서에도 같은 사실이 있다 | 그 후보를 버린다 |
| 답 없는 질문인데 세상에는 답이 있다 | 그 후보를 버린다 |
| 유형이 애매하거나 정답이 여러 개로 읽힌다 | 고쳐 쓰지 않고 버린다 |
| 한 칸의 후보가 전부 버려졌다 | "한 칸만 다시 요청할 때"를 쓴다 |
| 임시 채팅이 끊겼다 | 새 채팅에 지시서와 문서를 다시 올린다. 이미 고른 질문의 질문 문장을 "겹치지 않게 할 때"로 함께 붙인다 |
| AI가 문서에 없는 내용으로 정답을 만든 것 같다 | 그 후보를 버린다. 같은 일이 여러 번이면 지시서의 첫 문단을 다시 붙이고 다시 요청한다 |
| 무엇을 해야 할지 모르겠다 | 멈추고 Claude에게 묻는다. 아래 "물어도 되는 것"을 지킨다 |

## Claude에게 물어도 되는 것과 안 되는 것

| 물어도 되는 것 | 안 되는 것 |
|---|---|
| 절차, 형식, 칸의 뜻, 규칙의 해석 | 질문 문장, 정답, 근거 구절을 붙여 넣는 것 |
| 형식 검사 스크립트의 메시지 | "이 질문이 괜찮은가"처럼 내용을 판단해 달라는 것 |
| 어느 칸이 몇 개 모자라는지 | 실제 후보를 예로 드는 것 |
| 지어낸 다른 예로 "이런 경우는 어느 유형인가"를 묻는 것 | 화면을 그대로 캡처해 보여 주는 것 |

실수로 내용을 보여 줬으면 그 사실을 `DECISIONS.md`에 적고, 보여 준 질문은 최종 평가용에서 빼고 여분의 후보로 바꾼다.
