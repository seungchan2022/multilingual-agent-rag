# 세션 마무리

다음 세션의 Claude는 이 대화를 기억하지 못한다. 적어 둔 것만 넘어간다. 먼저 이슈가 **중간**인지 **끝**인지 가린다. 애매하면 사용자에게 묻는다.

## 공통 (중간이든 끝이든)

1. **바뀐 것을 확인한다.** `git status --short`와 `git diff --stat`으로 이번 세션에서 바뀐 파일을 본다. 내가 바꾸지 않은 변경이 있으면 건드리지 않고 알린다.
2. **문서를 갱신한다.** 새 정보만, 맞는 곳 한 군데에 적는다.
   - 결정 표(`decisions/` 아래. 어느 파일인지는 `DECISIONS.md`의 "새로 적는 곳"): 이번 세션에서 방식을 정한 것. 날짜, 결정, 정한 사람, 이유.
   - 판단 기록 표(`decisions/judgments.md`): 결과를 보고 내린 판단. 본 결과, 근거와 기준, 판단, 다음 액션. 구현이 틀려 서브에이전트의 effort를 올렸으면 여기에 적는다.
   - `STEPPER.md`: 계획이 바뀌었을 때만.
   - `DECISIONS.md` 미정 목록: 이번 세션의 결정 때문에 뒤 단계에 새로 생긴 일. 무엇을 어느 단계에서 할지 적는다. 결정을 기록하는 커밋에서 함께 적는 것이 원칙이고, 여기서는 빠진 것이 없는지 본다.
   - 이슈 체크리스트: 완료 기준을 채운 항목에 체크한다(`gh issue edit`).
3. **확인하지 못한 것을 가른다.** 확인하지 못한 것을 그대로 넘기지 않는다. 하나씩 "지금 확인할 수 있는가"를 묻고 셋으로 가른다. 지금 해야 할 일을 하지 않은 것과 지금은 할 수 없는 것이 한 이름 아래 섞이면, 읽는 사람이 어느 쪽인지 알 수 없기 때문이다.
   - 지금 확인할 수 있는 것: 이 자리에서 확인하고 목록에서 뺀다. 이슈가 중간이라 못 하면 `HANDOFF.md`의 남은 항목에 적는다.
   - 뒤 단계가 되어야 확인되는 것: `DECISIONS.md` 미정 목록에 다룰 단계와 함께 적는다. 그 단계를 시작할 때 이슈 체크리스트로 옮겨지고 닫을 때 대조된다. 스텝퍼의 그 단계 줄이나 미정 목록에 이미 있으면 다시 적지 않는다.
   - 확인할 방법이 없는 것: 한계다. 왜 확인할 수 없는지를 붙여 `HANDOFF.md`의 한계에 적는다.
4. **`HANDOFF.md`를 쓴다.** 아래 양식으로 덮어쓴다. 지난 내용은 커밋 기록에 남는다.
5. **커밋한다.** 이번 세션에서 바뀐 파일만 경로를 지정해서 stage한다. `git add -A`와 `git add .`는 쓰지 않는다. 한 커밋에 한 가지 변경만 담는다. 푸시하지 않는다.
6. **사용자에게 알린다.** 무엇을 확인했는지, 뒤 단계로 넘긴 확인과 한계, 남은 문제, 다음 세션이 할 일을 짧게 알린다.

## 이슈가 중간일 때

- 끝나지 않은 작업의 변경은 `유형: [진행 중] 제목 (#번호)` 커밋 하나로 남긴다. 이 커밋은 브랜치의 맨 위에 하나만 둔다.
- 이슈는 열어 둔다. 합치지 않는다. Codex 검토를 돌리지 않는다.
- `HANDOFF.md`에 정확히 멈춘 지점과 다음에 할 작은 작업 하나를 적는다.

## 이슈가 끝났을 때

공통 1~3을 한 뒤 아래를 순서대로 한다.

검토의 순서(완료 기준 대조, 어드바이저 점검, Codex 검토, 2차 뒤의 확인)는 `STEPPER.md` 공통 규칙의 "단계를 닫는 절차"를 따른다. 아래 1, 3, 4번은 그 절차를 풀어 쓴 것이고, 어긋나면 `STEPPER.md`가 맞다. 이 검토들은 보통 이 스킬을 부르기 전에 작업하는 세션 안에서 한다. 이미 했으면 다시 하지 않고, 했다는 것을 `decisions/judgments.md`의 판단 기록에서 확인한다.

1. **완료 기준 대조.** `STEPPER.md`의 완료 기준을 하나씩 대조한다. 기준마다 무엇으로 확인했는지 적는다. 하나라도 통과하지 못하면 이슈는 끝난 것이 아니다. `DECISIONS.md` 미정 목록에서 "다룰 단계"가 이 단계인 줄도 하나씩 대조한다. 처리한 줄은 지우고, 처리하지 못한 줄은 이유와 함께 다룰 단계를 고쳐 적는다. 과제 요구 요약(`.codex/assignment-requirements.md`)에서 이 단계가 맡은 것이 빠지지 않았는지도 본다. 체크리스트에 처음부터 없던 일은 체크리스트만 대조해서는 드러나지 않기 때문이다.
2. **맨 위가 `[진행 중]` 커밋이면 정식 커밋으로 고쳐 쓴다.**
3. **Codex 1차 검토.** `.codex/review-prompt.md`의 실행 방법대로 돌린다. 결과의 지적 원문과 처리 내용을 `CODEX_REVIEW.md`에 적는다. 지적마다 내 판정(동의, 일부 동의, 동의하지 않음)과 근거를 붙여 사용자에게 보여 준다. 반영 여부는 사용자가 정한다.
4. **Codex 2차 검토.** 고친 뒤 한 번 더 돌린다. 2차에서는 심각한 지적만 반영한다. 보통 이하는 `DECISIONS.md`의 미정 목록에 다룰 단계와 함께 적는다. 3차는 돌리지 않는다.
5. **사용자 승인.** 승인을 받기 전에는 합치지 않는다.
6. **검토 기록 정리.** `CODEX_REVIEW.md`를 커밋한 뒤 지우고, 지운 것도 커밋한다.
7. **`HANDOFF.md`를 쓰고 브랜치에서 커밋한다.** "진행 중인 이슈 없음"과 다음 이슈를 적는다. `main`에서는 커밋할 수 없으므로 합치기 전에 한다.
8. **합치기.** `git switch main && git merge --ff-only <브랜치> && git branch -d <브랜치>`.
9. **이슈 닫기.** 아래 "마무리 댓글 양식"으로 댓글을 달고 닫는다. 서브이슈가 모두 닫히면 큰 이슈도 닫는다.
10. **푸시할 명령을 사용자에게 적어 준다.** 직접 실행하지 않는다. 푸시됐는지는 `git fetch origin` 뒤 `origin/main`과 `HEAD`를 비교해서 확인한다.

0단계처럼 이슈와 Codex 검토가 없는 작업은 3, 4, 6, 9번을 건너뛴다.

## 마무리 댓글 양식

맨 위의 요약은 사용자가 읽는 글이다. 이 요약만 읽고 무슨 작업이었는지 알 수 있게 쉬운 말로 쓰고, 파일 이름과 숫자는 꼭 필요한 것만 넣는다. 자세한 기록은 접어 둔다.

```
## 요약

- 무엇을 했나: <한두 줄>
- 왜 했나: <한 줄>
- 달라진 것: <이 작업 뒤에 달라지는 것. 없으면 줄을 뺀다>
- 남은 것: <뒤로 넘긴 것과 한계. 없으면 없음>

<details>
<summary>자세한 기록</summary>

### 한 일
### 확인한 방법 (완료 기준마다)
### Codex 검토 (지적 수, 반영한 것, 반영하지 않은 것과 이유)
### 남긴 것
### 승인

</details>
```

## `HANDOFF.md` 양식

```
# 인계

**지금**: <단계와 이슈 번호, 이름> · <진행 중 / 진행 중인 이슈 없음> · <어디까지 됐는지 한 줄>
**다음**: <다음에 할 작은 작업 하나>

---

## 다음 세션의 Claude에게

- 브랜치:
- 맨 위 커밋: <이 파일을 넣는 커밋의 제목. 해시는 적지 않는다. 그 바로 아래 커밋의 해시와 제목을 함께 적는다. [진행 중]이면 그렇다고>
- 끝낸 항목:
- 남은 항목:
- 정확히 멈춘 지점:
- 커밋되지 않은 변경: <없음 / 무엇이 왜>
- 구현용 서브에이전트 effort: <이 이슈에서 지금 단계>
- 주의할 점:
- 뒤 단계에서 확인되는 것: <미정 목록에 적은 줄을 무엇을 어느 단계로 넘겼는지 한 줄씩. 없으면 없음>
- 한계: <확인할 방법이 없는 것과 그 이유. 없으면 없음>
- 읽어야 할 결정: <decisions/의 어느 파일, 어느 줄(날짜와 첫 구절)>
```

맨 위 두 줄은 사용자가 상태를 보는 용도다. 사용자가 그 두 줄만 읽고도 알 수 있게 쓴다.

`HANDOFF.md`는 세션의 맨 마지막 커밋으로 넣는다. 이 파일을 넣는 커밋의 해시는 커밋하기 전에는 알 수 없으므로 적지 않고, 그 바로 아래 커밋의 해시를 적는다. `HANDOFF.md`를 커밋한 뒤에 다른 커밋을 더했으면 `HANDOFF.md`를 다시 써서 맨 위에 오게 한다.

## 하지 않는 것

- 확인하지 않은 것을 끝났다고 적지 않는다. 사용자가 말한 것, 파일로 확인한 것, 직접 실행한 것을 구분해서 적는다.
- `HANDOFF.md`와 문서에 최종 평가용 질문과 정답, 비밀값, 대화 전체를 적지 않는다.
- 다음 단계의 작업을 시작하지 않는다.
- `git push`를 하지 않는다.
